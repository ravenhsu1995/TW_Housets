## 涵蓋率檢查：十層

下載範圍是**發布季**、分析窗口是**交易季**，兩者錯開。少了幾個發布季，對應的交易月會被
系統性少算，而密度數字照樣算得出來、圖也畫得出來——**這類錯誤沒有自然的失敗訊號**。
所以在算密度之前先擋十層（`COVERAGE_STRICT` 控制中止，細節見 notebook §1、§3.2）：

| 層 | 抓什麼 |
|---|---|
| 1 | 發布季／縣市主檔缺檔、檔案數與 `SEASONS` 不一致 |
| 2a / 2a′ | 來源欄名改版；日期率與型態佔比異常（基準是**同縣市鄰近 7 季**的中位數，對長期趨勢免疫） |
| 2a″ / 2a‴ | 某種型態的用語從某季起**完全**改掉（逐季普查）／**部分**改掉（季序列階梯） |
| 2b / 2b′ | （發布季 × 縣市）筆數異常、季序列的持續性階梯落差 |
| 3 | 逐月交易量離群（局部滾動中位數 ＋ 同月跨年 雙基準） |
| 4 | **對官方買賣移轉棟數的比值**——等比例少算那一類 |
| 5 | 對上次成功執行的季筆數與型態組命中數快照 |

**為什麼需要 Layer 4：** 第 1–3 層的基準幾乎都從資料自身算出，對「基準被污染」結構性
無免疫——全窗口等比例少算會讓所有基準一起沉、相對值不變、全層綠燈。Layer 4 換一個
體制外的分母（官方按縣市 × 登記月公布的買賣移轉棟數），這是唯一擋得住那一類的檢查。
批次檔的發布季對應登記季（落後一季），兩者邊界對不齊，所以形狀檢查用四季滾動和、
絕對水準用整個窗口的總和。**看 `passed` 之前先看 `external_anchor.status`。**

**Layer 5** 是退一步的版本：把每個（發布季 × 縣市）的可解析列數存成快照，下次執行拿來比。
不需要外部來源，只要上一次是好的連等比例少算都擋得住；代價是第一次執行沒有基準。
快照**只在本次全部通過時才更新**（不然壞的一次會變成往後的基準），且不進版控——
新 clone 的第一次執行一定是 `first_run`。

**門檻已用真實資料校準過一輪**（2026-08-25、36 個發布季、143 萬筆）：

| 門檻 | 值 | 真實資料實測 |
|---|---|---|
| 2a′ 住宅類佔比（局部） | 0.60 | 最小 0.840（臺南） |
| 2a′ 主型態佔比（局部） | 0.45 | 最小 0.659（臺南 114S1） |
| Layer 4 比值區間 | 0.61 – 2.50 | 0.876（臺北）~ 1.404（臺南） |

**Layer 4 的比值大於 1 是正常的**：我方分子是「可解析列數」，含純土地／純車位標的，
而官方買賣移轉棟數不算它們。原本設 1.15 會誤報四個縣市。

還沒用真實資料校準的：2b 的 0.35、2b′ 與 2a‴ 的 0.55/2.5、Layer 3 的 0.40。
**注意門檻餘裕的偏差有方向**——合成資料會低估誤報餘裕（保守）、**高估偵測邊界（危險）**，
所以合成資料上量到的「偵測得到 f ≥ X」一律當樂觀值看。

## 粒度決策規則（計畫 §5.0）

依序檢查，第一個讓「n ≥ 5 的 cell 佔比 > 50%」的方案勝出：
村里×月 → 村里×季 → 鄉鎮市區×月 →（全不過）放寬建物型態重跑。

**佔比的分母含零交易 cell**（單元母體 × 期數）。只算有交易的 cell 會嚴重高估密度。

### 村里粒度沒有精確解

實價登錄批次資料**沒有村里欄位、也沒有座標**，只有鄉鎮市區與門牌。精確的村里歸屬需要
地址 geocoding，那是 NB2 的工作。NB0 用三種方式在不做 geocoding 的前提下逼近：

- **A 理論上限** — 嚴格數學上界（任何空間分布都不可能超過）。上限若 ≤ 50%，村里粒度確定出局
- **B 戶數比例分配** — 「完全無空間聚集」虛無情境
- **C 街道聚集情境** — 用門牌路段的實際聚集程度模擬

恆有 A ≥ C。**決策以 A 為準**，因為只有它不會因估計方法失準而翻案。鄉鎮市區粒度則是精確計算。

## 資料來源的三個坑

NB0 已處理，但改動清整規則時要留意：

1. **不要用「預售」比對備註來排除交易。** 實價登錄 2.0 的制式備註是「預售屋、或土地及建物分件登記案件；」——兩件事包在同一句，而絕大多數是後者（一般成屋的登記方式）。用「預售」比對會誤殺約 41% 的成屋交易。真正的預售屋另存於 `*_lvr_land_b.csv`，NB0 根本沒讀。
2. **檔名的「季」是發布季不是交易季。** `106S1` 內含的是民國 105 年 10–12 月登記的案件。下載範圍必須比分析期間寬，再用 `交易年月日` 過濾。Layer 4 的外部錨也靠這個對應關係（`ANCHOR_LAG_Q = 1`）。
3. **改 `KEEP`（寫給 NB2 的欄位）時要一起改 `USE_COLS`。** `load_one()` 只讀 `USE_COLS` 列出的欄位（36 季全欄位讀進來會 OOM）。只加 `KEEP` 不加 `USE_COLS`，parquet 就會少那一欄——§3.5 有一道明確的缺欄警告接這個情況。

另外，實價登錄 2.0（民國110年7月）前後有欄位改名（`車位移轉總面積(平方公尺)` → 去掉括號），
由 `COL_ALIASES` 統一；若未來又改名，`load_one()` 會印出明確警告而不是丟 KeyError。

記憶體：`load_one()` 在載入時就篩住宅類、只讀用得到的欄位、把數值欄與日期欄轉掉。
載入後會印出 `raw` 的逐欄用量與**行程 RSS 高水位**（含 `pd.concat` 的瞬時峰值）——
要判斷 36 季會不會在 Colab 免費版 OOM，看那個數字，不要看推估。
